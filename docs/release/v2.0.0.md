# cli-forge v2.0.0 — Themed output, a real argument model, and a seam for the suite

`docs/API.md` froze the 1.x surface "until 2.0". This is that release. It does
three things:

1. **Makes output themed and reusable.** The headline, and the thing 1.x got
   wrong: a named style carried colour only, so every status line rebuilt its own
   marker by hand. A `Style` now carries its whole appearance and a `Theme` states
   a program's vocabulary once.
2. **Gives the command layer the argument model a real CLI needs** — and fixes
   four defects that each made a legitimate command line unparseable.
3. **Turns the styling and measurement layers into seams** the sibling crates can
   actually build on, which they could not before.

Migrating is a handful of renames. See the
[migration table](../../CHANGELOG.md#migrating-from-1x).

## The problem this release is really about

Here is the status-line helper from the 1.x `status_report` example:

```rust
fn step(label: &str, status: Status) {
    let name = match status {
        Status::Ok => "ok",
        Status::Warn => "warn",
        Status::Fail => "fail",
    };
    // Pad the text to a fixed width *before* styling it, so the visible columns
    // line up whether or not color is applied.
    let marker = tag(name).render_with(&format!("{:<6}", format!("[{name}]")));
    out(format!("  {marker} {label}"));
}
```

Three things are being done by hand that the library should own: mapping a status
to a style name, building a padded marker, and knowing that padding must happen
before styling because escape bytes would otherwise be counted. And the padding
is still wrong — `{:<6}` counts bytes, so a non-ASCII label skews the column.

The 2.0 version:

```rust
fn step(label: &str, status: Status, detail: &str) {
    let line = format!("{} {}", named("step").paint(label), named("detail").paint(detail));
    match status {
        Status::Ok => ok(line),
        Status::Warn => warn(line),
        Status::Fail => fail(line),
    }
}
```

The glyph comes from the theme, the width from the named style, and both are
measured in display columns. Changing how the program looks means changing the
theme, not this function.

## Themed responses

A `Theme` maps each of the eight `Level`s a CLI speaks in onto a style, a glyph,
and a stream:

```rust
Theme::new()
    .set(Level::Success, Style::new().bright_green().bold(), "✓")
    .set(Level::Error, Style::new().bright_red().bold(), "✗")
    .set_glyphs(Glyphs::Auto)
    .install();

ok("deployed to staging");
warn("2 tests skipped");
fail("smoke test failed");
```

Three details the hand-rolled version usually gets wrong, which the theme owns:

- **Stream discipline.** Errors, warnings, and diagnostics go to standard error;
  data, hints, and notes to standard output. A program's output is therefore
  pipeable without the program arranging it.
- **Glyph fallback.** Under `Glyphs::Auto`, `✓` becomes `+` where the destination
  cannot render it — and every ASCII stand-in is one column wide, so a column of
  status lines stays aligned either way.
- **Per-stream colour.** Each line renders at the depth detected for the stream it
  is going to, so colour survives on a terminal and vanishes in a pipe,
  independently for each.

`Theme::plain()` is what a `--plain` flag should install. A theme is a plain
value, so a library can render through its own without disturbing its host's.

## Styles carry their decoration

```rust
define("step", Style::new().bright_black().prefix("  → ").pad_to(24));

let step = named("step");
for label in ["resolve dependencies", "compile", "link"] {
    out(step.paint(label));
}
```

`Style` gained `prefix`, `suffix`, `pad_to`, `align`, `link` (OSC 8 hyperlinks),
and `merge`, plus `paint` — which applies one style to any number of values
without allocating. `pad_to` measures display columns, so the column holds for
ASCII, accented, CJK, and already-styled content alike.

The colour model is now complete: all sixteen terminal colours including the
bright half, the 256-colour palette, exact 24-bit values, backgrounds throughout,
and eight attributes. An exact colour degrades to the nearest the terminal can
render — through the greyscale ramp as well as the cube, using
weighted-luminance distance, which stopped mid greens resolving to black.

## The `text` module

Everything that lines things up needs one correct answer to "how many columns is
this?", and `str::len` is not it once escape sequences are involved. `text::width`,
`strip`, `pad`, `truncate`, `wrap`, and `sanitize` are that answer, and they are
the seam a table or progress crate cannot work without.

`text::sanitize` also closes a real hole: 1.x wrote untrusted text verbatim, so a
hostile filename could clear the screen, reposition the cursor to overwrite
earlier output, or change the terminal's colours permanently.

## Four fixed defects

Each was reproduced before being fixed:

| Invocation | 1.x result |
|---|---|
| `calc add -5 3` | `UnknownFlag { flag: "-5" }` — negative numbers were unparseable |
| `demo --verbose build` | `UnknownFlag` — there were no app-level arguments at all |
| `remote list` | `MissingRequired { arg: "name" }` — a parent's positionals were demanded even when a subcommand took over |
| any non-UTF-8 argument | **panic**, because `std::env::args` panics |

Two more, in the output layer: help columns were aligned by byte length, so a
command named `日本語` skewed every row; and standard error's styling was decided
by standard output's capability, so a program with one stream redirected got one
of the two wrong.

## The argument model

```rust
Command::new("build")
    .arg(Arg::option("jobs").short('j').default("1").value_name("N")
        .validate(|v| v.parse::<u16>().map(|_| ())
            .map_err(|_| "expected a count".to_string())))
    .arg(Arg::option("level").possible_values(["warn", "info", "debug"]))
    .arg(Arg::option("token").env("FORGE_TOKEN"))
    .arg(Arg::flag("quiet").conflicts_with(["verbose"]))
    .arg(Arg::positional("file").required(true).required_unless(["stdin"]))
```

Values are checked **at the edge**, so a bad one is refused with a proper
command-line error naming the flag, the value, and what would have been accepted —
before any of the program's code runs. Reading them back then cannot fail for a
reason the user caused:

```rust
let jobs: u16 = m.get("jobs").unwrap_or(1);
```

`Matches::source` reports whether a value came from the command line, the
environment, or a default — the distinction a sentinel default cannot express.

App-level arguments arrived with `App::arg`, and `Arg::global` makes one usable on
either side of the command name, recorded once and visible at every level.

## Errors that answer "what now?"

```text
error: unknown flag '--releaze'

  did you mean '--release'?

USAGE: forge build [options] [targets]...
```

A `ParseError` carries the subject, what would have been valid, the nearest
spelling to what was typed, and the usage line of the command being invoked.
Suggestions cover commands, subcommands, flags, and the members of a
`possible_values` set.

Help and version come back through the same channel but are **successes**:
`exit_code()` is `0` and `stream()` is standard output, so `--help` can be piped.
A bad command line exits `2`; a failed command exits `1`, or its own status via
`Command::run_status`.

## Parsing and dispatch are separate

The one silent behaviour change. In 1.x, `try_parse_from` ran handlers as a side
effect of parsing, which made the testing entry point the one with side effects.
Now:

| Method | Parses | Runs handlers | Prints | Exits |
|---|---|---|---|---|
| `run` | process args | yes | yes | returns a code |
| `parse` | process args | yes | yes | yes |
| `try_run_from` | given args | yes | no | no |
| `try_parse_from` | given args | no | no | no |

A program relying on `try_parse_from` to dispatch will stop running handlers.
`App::parse` and `App::run` still dispatch.

## For the suite

cli-forge is the base every higher CLI layer builds on, and 1.x could not actually
serve that role: there was no way to measure styled text, no way to override
colour, and — fatally — no public accessor on `App`, `Command`, or `Arg`, so a
completions or manual-page generator could not read the command tree at all.

All four are now seams:

- `text::width` / `strip` / `pad` / `truncate` / `wrap`
- `Style` / `Color` / `Theme`, so a table's borders honour the host's theme
- `terminal::level` / `size` / `supports_unicode`, one capability decision
- `App::commands` / `Command::arguments` / `Arg::allowed_values` and the rest

## A real `no_std` build

`--no-default-features` was an empty crate in 1.x — every module was gated on
`std`, and the integration tests did not even compile. It is now a genuine build
of the styling core (colour, style, text, markup, themes) on `alloc` alone, with
its own 180 tests passing, for a sink whose capability the caller declares with
`terminal::set_level`.

## Performance

The styling path got measurably faster: every escape sequence this crate writes is
drawn from a small fixed set of codes, but each went through `core::fmt`'s integer
formatter, which cost more than the rest of writing a styled run put together.

| Benchmark | 1.x | 2.0 | |
|---|---|---|---|
| `paint_named_colour` | 160 ns | 103 ns | −36% |
| `paint_exact_colour` | 316 ns | 184 ns | −40% |
| `paint_downgraded_to_16` | 201 ns | 138 ns | −31% |
| `markup_rich` | 409 ns | 234 ns | −42% |
| `theme_render` | 246 ns | 167 ns | −30% |

The plain path (`out` / `err`) is byte-for-byte unchanged at ~9.5 ns and remains
allocation-free, which `tests/allocation.rs` asserts by measurement rather than by
claim.

## The SemVer promise

- **No breaking change before 3.0.** Every public item's signature and documented
  behaviour — including the `auth` seam, the feature flags, and the read-only
  accessors — is guaranteed. A breaking change requires a MAJOR bump.
- **Additions are minor.** New public API arrives only in `2.x` releases and is
  strictly additive. `ErrorKind`, `Color`, and `AuthRequest` are
  `#[non_exhaustive]` so new cases can be added without one.
- **Fixes and optimisation are patch.**
- **The 1.85 MSRV rises only in a minor release.**
